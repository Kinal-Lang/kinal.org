Design principles

The choices behind Kinal’s syntax, safety levels and execution backends.

Code structure

Functions, classes, interfaces and modules organize code at different levels. Declarations make types, visibility and dependencies explicit.

Language reference→

Safety levels

Safe, Trusted and Unsafe define where operations and calls are permitted. They do not manage foreign resources automatically. Pointer lifetimes still follow the API’s ownership rules.

Safety reference→

Native interoperability

Kinal connects to native libraries through the C ABI. Function signatures, calling conventions, integer widths and resource ownership must match the library and target platform.

FFI conventions→

Backend differences

Native and KinalVM share the language frontend, but their runtime support differs. Check the documented capabilities and limitations when choosing a backend.
