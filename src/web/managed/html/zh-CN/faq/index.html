开始使用

什么是 Kinal？

Kinal 是一门开源、静态类型的通用编程语言，支持 LLVM 原生编译和 KinalVM 字节码执行。

Kinal 是开源的吗？

是的。Kinal 在 GitHub 上开源开发：Kinal-Lang/Kinal。欢迎贡献。

可以不安装就试用 Kinal 吗？

可以。在在线运行页面中编辑示例，点击“运行”即可查看结果。

学习曲线如何？

如果使用过 C#、Java 或其他 C 系语言，Kinal 的函数和控制流语法会比较熟悉。可以从 Hello World 教程开始。

有 IDE 支持吗？

Kinal VS Code 扩展提供高亮、LSP 诊断、补全、定义跳转、格式化、运行和创建项目命令。安装完整工具链并配置编译器及 LSP 路径；工程边界由最近的 kinal.knproj 决定。

平台与互操作

Kinal 支持哪些平台？

Native 目标包括 Windows、Linux、macOS 的 x64／ARM64，以及 Windows x86 和受支持的 freestanding 目标。具体发行包、SDK、原生资产和 API 支持范围应分别核对；IO.UI 当前使用 Windows Win32 后端。

可以从 Kinal 调用 C 库吗？

可以，使用 Extern 声明函数，使用 Delegate 描述函数指针。Native ABI、调用约定、C 整数宽度和指针生命周期必须匹配；任意 C 库调用不是通用 VM 能力。

Native 和 VM 的功能相同吗？

不是。当前 C KNC 后端在一般 Await、Task Run、集合创建、接口分派和原生 FFI 等路径有限制。先阅读后端支持表，再验证具体示例。

Kinal 如何标记危险操作？

Kinal 通过 Safe、Trusted 和 Unsafe 表达操作边界。具体规则见安全设计与内存和生命周期。

Kinal 支持面向对象的原生程序吗？

Kinal 提供常见的类、接口和属性语法，并可通过 LLVM 编译为原生程序，通过 C ABI 实现互操作。

工具链与发行版

可以只复制编译器可执行文件吗？

应保留完整发行目录，包括 LLVM、链接器、运行时、标准包和 LSP。已生成 Native 程序和打包 VM 程序也可能依赖系统或包动态库。

如何管理多个源文件？

使用 kinal.knproj 的 SourceSet 与 Profile，选择 FileOnly、EntryUnit、ReachableUnits 或 AllSources。Get 控制可见性，不会越过活动源码集合边界。

文档与发行版不一致时怎么办？

本参考跟随当前 C 源码。先检查 kinal --version 和 kinalvm --version，再核对安装包与当前源码差异；源码常量和 KNC 文件格式版本是不同概念。

Kinal 编译器是自举的吗？

本网站文档以当前 C 实现的编译器为基准。仓库中的其他编译器实现和实验不代表 C CLI 已提供同名命令或相同行为。标准包与 KinalVM 使用 Kinal，并通过必要的原生桥接连接宿主环境。
