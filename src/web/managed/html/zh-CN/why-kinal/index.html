设计原则

Kinal 在语法、安全等级和运行后端上的主要设计取舍。

代码结构

函数、类、接口和模块用于组织不同层次的代码。类型、可见性和依赖关系通过声明表达。

语言参考→

安全等级

Safe、Trusted 和 Unsafe 标记操作和调用的范围。安全等级不等于自动管理外部资源，指针生命周期仍需遵守所调用 API 的约定。

安全等级参考→

原生互操作

Kinal 通过 C ABI 与原生库互操作。函数签名、调用约定、整数宽度和资源所有权需要与外部库匹配，并按目标平台核对。

FFI 约定→

后端差异

Native 与 KinalVM 共用语言前端，但支持的运行时功能不完全相同。文档分别说明两种后端的能力和限制，选用后端时需要核对。
